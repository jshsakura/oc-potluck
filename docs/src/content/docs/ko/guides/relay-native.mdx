Docker는 필수가 아닙니다. `server/src/LanPlayServer.csproj`를 빌드해 중계 서버를 직접 실행할 수 있습니다. 아래는 **Linux에서 .NET 런타임으로 실행하는 방법**입니다. NAS에서 컨테이너로 운영하려면 [Docker Compose](../relay-server/) 또는 [시놀로지 안내](../synology/)를 사용하세요.

## 준비물

- Git과 **[.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0)**. 현재 프로젝트의 대상 프레임워크는 `net10.0`입니다. 빌드한 DLL을 다른 호스트로 옮긴다면 그 호스트에도 .NET 10 런타임이 필요합니다.
- **JSON 명령을 지원하는 Redis**. 예를 들어 Redis 8 또는 RedisJSON이 포함된 Redis Stack을 사용할 수 있습니다. 현재 서버는 시작할 때 Redis에 연결하고 `JSON.SET`을 호출하므로 Redis를 생략할 수 없습니다.
- 참가자가 접근할 수 있는 TCP 포트. 기본 중계 포트는 `30456`입니다.

Redis도 Docker 없이 설치할 수 있습니다. [Redis 설치 안내](https://redis.io/docs/latest/operate/oss_and_stack/install/install-stack/)를 따르되, Redis를 외부에 공개하지 마세요. 같은 호스트에서는 `127.0.0.1`에 바인딩하고 보호 모드를 유지합니다. 다른 용도로 사용하는 Redis와 인스턴스를 분리하세요. 서버는 시작 시 `ldn`과 `games` 통계 키를 초기화합니다.

```sh
redis-cli -h 127.0.0.1 -p 6379 ping
redis-cli -h 127.0.0.1 -p 6379 COMMAND INFO JSON.SET JSON.GET
```

첫 명령은 `PONG`, 두 번째는 두 JSON 명령의 정보를 반환해야 합니다. `PONG`만 나온다고 JSON 지원까지 확인된 것은 아닙니다.

## 소스 받기와 빌드

```sh
git clone https://github.com/jshsakura/oc-potluck.git
cd oc-potluck
dotnet --version
dotnet publish server/src/LanPlayServer.csproj -c Release \
  -p:PublishAot=false -p:UseAppHost=false --self-contained false \
  -o ./output/relay
```

프로젝트의 기본값은 Native AOT이지만, 위 명령은 .NET 런타임용 DLL로 배포해 별도의 네이티브 컴파일러 없이 시작하도록 합니다. `output/relay/` 전체를 함께 보관하세요. `LanPlayServer.dll`뿐 아니라 의존성 파일과 `gamelist.json`도 필요합니다. 배포 옵션은 [.NET 공식 안내](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-publish)를 참고하세요.

운영에 사용할 때는 검토한 릴리스 태그나 커밋을 선택해 빌드하세요. 모듈 빌드용 devkitPro나 Atmosphere 하위 모듈은 중계 서버 빌드에 필요하지 않습니다.

## 환경 변수로 실행

```sh
cd output/relay
mkdir -p data
LDN_HOST=0.0.0.0 \
LDN_PORT=30456 \
LDN_REDIS_HOST=127.0.0.1 \
LDN_REDIS_PORT=6379 \
LDN_GAMELIST_PATH="$PWD/gamelist.json" \
IP_BAN_FILE_PATH="$PWD/data/bannedips.txt" \
dotnet ./LanPlayServer.dll
```

루트 계정이 아닌 사용자로 실행하세요. `data/`는 그 사용자가 쓸 수 있어야 합니다. 차단 목록 파일은 없으면 생성하지만 부모 디렉터리는 먼저 만들어야 합니다. 이 예제는 현재 터미널에서 실행되며 `Ctrl+C`로 종료합니다.

| 변수 | 기본값 | 역할 |
| --- | --- | --- |
| `LDN_HOST` | `0.0.0.0` | 중계 리스너가 사용할 실제 호스트 주소 |
| `LDN_PORT` | `30456` | 중계 TCP 포트. Docker의 포트 매핑 없이 직접 사용 |
| `LDN_GAMELIST_PATH` | `gamelist.json` | 게임 이름 목록. 상대 경로는 실행 디렉터리 기준 |
| `LDN_REDIS_HOST`, `LDN_REDIS_PORT` | `127.0.0.1`, `6379` | JSON 지원 Redis 연결 주소 |
| `LDN_REDIS_SOCKET` | 빈 값 | 설정하면 Redis 호스트·포트 대신 Unix 소켓 사용 |
| `IP_BAN_FILE_PATH` | `bannedips.txt` | 보관할 IP 차단 목록 경로 |
| `LDN_STATUS_HOST`, `LDN_STATUS_PORT` | `127.0.0.1`, `0` | 읽기 전용 `/rooms` 상태 API. 포트 `0`이면 꺼짐 |

Compose용 `LDN_BIND_IP`와 `LDN_SERVER_IMAGE`는 서버 프로그램이 읽는 설정이 아닙니다. 직접 실행할 때는 `LDN_HOST`를 사용합니다. `.env` 파일도 자동으로 읽지 않으므로 셸이나 서비스 관리자를 통해 환경 변수를 전달하세요.

## 기기 연결과 상시 운영

PotLuck에 호스트의 LAN IP 또는 외부에서 접근 가능한 호스트명과 포트를 입력합니다. 원격 참가자에게 필요한 중계 TCP 포트만 방화벽·라우터에서 허용하세요. Redis 6379와 상태 API를 함께 공개할 필요는 없습니다. 자세한 네트워크 설명은 [NAS 네트워크](../synology/)를 참고하세요.

상태 API가 필요하면 `LDN_STATUS_PORT=30457`을 추가하고 기본 루프백 주소를 유지하세요. HTTPS 웹 페이지에 연결하려면 역방향 프록시를 통해 읽기 전용 API만 제공합니다. 이 HTTP API와 게임 중계 TCP 포트는 별개입니다.

장기 운영은 systemd 같은 서비스 관리자를 사용하고, 실행 디렉터리·환경 변수·전용 사용자·재시작 정책·메모리와 로그 상한을 지정하세요. 종료할 때는 `SIGTERM`이나 `Ctrl+C`로 정상 종료합니다. 업데이트 전에는 참가자에게 알리고 차단 목록과 설정을 백업한 뒤 서버를 중지하세요. 실행 중인 파일을 덮어쓰지 말고 새 배포 디렉터리로 교체하면 이전 빌드로 돌아가기 쉽습니다.

## Native AOT로 배포하기

.NET 런타임 설치 없이 실행할 바이너리가 필요하면 프로젝트의 기본 Native AOT 배포를 사용할 수 있습니다. 대상 OS·CPU에 맞는 빌드 환경과 네이티브 도구가 필요합니다. [Native AOT 준비 사항](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/)을 먼저 확인하세요.

저장소 루트로 이동한 뒤 실행하세요. Ubuntu·Debian 계열 Linux x64에서 같은 플랫폼용으로 빌드하는 예:

```sh
dotnet publish server/src/LanPlayServer.csproj -c Release \
  -r linux-x64 -p:PublishAot=true -o ./output/relay-aot
cd output/relay-aot
# 위의 Redis·경로 환경 변수를 설정한 뒤 실행합니다.
./LanPlayServer
```

ARM64 Linux는 `linux-arm64`, Alpine 계열은 해당 `linux-musl-*` RID를 사용해야 하며 서로 바꿔 사용할 수 없습니다. 바이너리와 `gamelist.json`을 함께 배포하고 대상 OS의 런타임 라이브러리도 갖추세요. 직접 실행하더라도 채널은 검색 구분이며 통신 암호화나 사용자 인증 기능은 아닙니다.
