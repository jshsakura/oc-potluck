## 구성 요소의 역할

| 구성 요소 | 책임 |
| --- | --- |
| 설치 앱 | 배포 파일 다운로드·검증·설치, 설정·진단·삭제 |
| `ldn:u` MITM | 게임 LDN 상태·검색·방 수명 관리 |
| `bsd:u` MITM | 가상 LDN 소켓 통신을 선택한 백엔드로 전달 |
| `potluck` IPC 서비스 | 오버레이에 실시간 모듈 상태·설정 제공 |
| 오버레이 | 설정·상태 표시. 게임 패킷 자체를 중계하지 않음 |
| 중계 서버·Redis | 원격 방 검색·패킷 중계와 통계 |

로컬은 LAN 백엔드를 사용해 서버가 필요 없습니다. 원격은 중계 클라이언트를 쓰며 빈 서버 주소는 실제 로컬로 동작합니다. 게임이 서비스를 열면서 백엔드를 잡으므로 모드 변경 후에는 게임 재시작이 필요합니다.

## 프로토콜과 제약

`sysmodule/source/main.cpp`의 공유 확장 힙은 384 KB입니다. 수신 큐·소켓·스레드 스택·동적 작업을 함께 계산해야 합니다. 실기에서는 고정 버퍼와 한도가 있는 큐가 중요합니다.

Wire 구조체는 C# 서버와 바이트 단위로 호환되어야 합니다. LDN 헤더는 정렬 패딩을 포함해 12바이트입니다. 빌드를 통과시키려고 패딩을 지우거나 크기 검증을 약하게 하지 마세요. [프로토콜](../../reference/protocol/)·[IPC 명령](../../reference/ipc-commands/)은 영어 원문 참조도 제공합니다.

게임의 PIA 네트워크는 LDN 위에서 동작합니다. 로컬 IP·노드 매핑과 같은 포트의 모든 수신 소켓으로 브로드캐스트 전달이 맞아야 메시 검색이 됩니다. 방 검색 성공만으로 게임 통신이 검증되지 않습니다.

## 소스 위치

| 경로 | 영역 |
| --- | --- |
| `sysmodule/source/ldn/` | 서비스·상태·패킷 분배·공유 상태 |
| `sysmodule/source/bsd/` | 소켓 가로채기·프록시 라우팅·큐 |
| `sysmodule/source/network/` | 중계 클라이언트·TCP·재연결 |
| `sysmodule/source/p2p/` | 선택적 직접 경로·UPnP |
| `sysmodule/source/config/` | INI·저장·설정 IPC |
| `overlay/`, `installer/` | 기기 사용자 인터페이스 |
| `server/src/` | 서버·프로토콜 구현 |

상세 구현은 현재 소스·관련 테스트를 확인하세요. 호스트 테스트·정적 문서는 [실기 확인](../building/)을 대신하지 않습니다.
